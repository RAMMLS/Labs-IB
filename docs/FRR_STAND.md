# Сетевой стенд Labs-IB для Apple Silicon

Стенд повторяет рабочий цикл из `Vesr.docx`: пустое поле, создание узлов с
параметрами, выбор интерфейсов при соединении, запуск, веб-консоль, сохранение
стартовой конфигурации, сброс и повторная загрузка. Лабораторная заранее не решена:
топологию, адреса и протоколы задаёт пользователь.

## Запуск

Из корня репозитория:

```bash
docker compose up -d --build
open http://127.0.0.1:8080
```

Остановка:

```bash
docker compose down
```

Узлы, кабели, координаты, параметры и стартовые конфигурации сохраняются в томе
`labs-ib_lab-data`. После следующего запуска ранее включённые ноды снова
запустятся, а ранее выключенные останутся выключенными.

## Сценарий из Vesr.docx

1. Нажать `Добавить объект`.
2. Выбрать `Eltex vESR — функциональный эквивалент FRR` или `Виртуальный ПК`.
3. Задать число узлов, имя, количество процессорных ядер, ОЗУ и сетевых портов.
4. Узел появится с красным индикатором и останется выключенным.
5. Нажать значок соединения на узле либо `Соединить узлы` в меню.
6. Выбрать второй узел, затем конкретные свободные интерфейсы с обеих сторон.
7. Запустить узлы кнопкой `▶` или через контекстное меню `Запустить`.
8. Кликнуть по запущенному узлу для открытия встроенной веб-консоли.
9. Настроить свою лабораторную и проверить связность.
10. Сохранить конфигурацию командой `commit`/`write memory` и действием
    `Экспортировать конфигурацию`.

В отличие от исходной методички, установочное меню vESR не показывается. Оно
нужно один раз при создании vendor qcow2; здесь эквивалентный базовый ARM64-образ
уже собирает Docker Compose.

## Интерфейсы

Маршрутизатор получает логические порты `gi1/0/1`, `gi1/0/2` и далее. VPC
получает `eth0`, `eth1` и далее. Диалог соединения показывает только свободные
порты. Метка рядом с концом кабеля — имя, которое надо использовать в задании.

Внутри Docker каждому подключённому порту соответствует технический Linux
интерфейс. Стенд автоматически сопоставляет `gigabitethernet 1/0/N` с ним. Это
сопоставление видно в верхней строке консоли и в `show interfaces status`.

Каждый кабель создаёт отдельный L2 bridge. Docker временно выдаёт адрес
`169.254.x.x`, чтобы стенд определил имя нового Linux-интерфейса, после чего
служебный адрес автоматически удаляется. Поэтому в RIP, OSPF и BGP участвуют
только учебные IP, которые пользователь добавляет самостоятельно.

## Консоль маршрутизатора

Консоль маршрутизатора работает поверх FRRouting. Доступны реальная статическая маршрутизация, RIP,
OSPF, BGP, IPv4 и IPv6. Консоль хранит текущий режим, поэтому команды можно
вводить по одной, как в Telnet:

```text
configure
interface gigabitethernet 1/0/1
ip address 192.0.2.1/24
exit
end
commit
```

Поддержаны совместимые команды `configure`, `commit`, `confirm`,
`reload system`, `show interfaces status` и имена `gi1/0/N`. Для полной
настройки протоколов используется синтаксис FRR/vtysh. Это функциональный
эквивалент, а не поддельная оболочка всего Eltex CLI.

## Консоль виртуального ПК

Основные команды:

```text
ip 192.0.2.2/24 192.0.2.1
show ip
ping 192.0.2.1
trace 192.0.2.1
arp
save
clear
```

`save` сохраняет текущие команды в стартовую конфигурацию. Для диагностики можно
переключить консоль в режим `Командная оболочка Linux`, где доступны `ip`, `ping`,
`traceroute`, `tcpdump`, `dig`, `curl` и другие утилиты.

## Сброс и стартовые конфигурации

- `Экспортировать конфигурацию` извлекает текущую конфигурацию запущенного узла.
- `Стартовые конфигурации` показывает сохранённый текст, позволяет его редактировать,
  скачивать и включать/отключать применение после сброса.
- `Сбросить` пересоздаёт контейнер из чистого образа, сохраняет узел и кабели и
  оставляет устройство выключенным.
- При следующем запуске включённая стартовая конфигурация будет загружена автоматически.

## Остальные действия

- `Редактировать` — имя, описание, процессорные ядра, ОЗУ и число портов. Нельзя убрать занятый порт.
- `Перезагрузить` — остановка и повторный запуск того же узла.
- `Захватить пакеты` — текстовый `tcpdump` выбранного порта: до 20 пакетов или 8 секунд.
- Двойной клик по кабелю — удалить соединение после подтверждения.
- Правый клик по узлу — полное меню действий.

## Проверка

```bash
./lab doctor
./lab test
./lab status
```

`./lab test` на пустом поле временно создаёт маршрутизатор и виртуальный ПК, выбирает
порты, настраивает тестовые IP, проверяет ping и цикл
`Экспорт конфигурации → Сброс → Запуск`, после чего полностью удаляет тестовую топологию.
