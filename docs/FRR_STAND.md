# Сетевой стенд Labs-IB для Apple Silicon

Стенд повторяет рабочий цикл из `Vesr.docx`: пустое поле, создание нод с
параметрами, выбор интерфейсов при соединении, запуск, HTML-консоль, сохранение
startup-config, wipe и повторная загрузка. Лабораторная заранее не решена:
топологию, адреса и протоколы задаёт пользователь.

## Запуск

Из корня репозитория:

```bash
docker compose up -d --build
open http://127.0.0.1:8080
```

Остановка:

```bash
docker compose down
```

Ноды, кабели, координаты, параметры и startup-конфигурации сохраняются в volume
`labs-ib_lab-data`. После следующего запуска ранее включённые ноды снова
запустятся, а ранее выключенные останутся выключенными.

## Сценарий из Vesr.docx

1. Нажать `Добавить объект`.
2. Выбрать `Eltex vESR — FRR functional equivalent` или `Virtual PC`.
3. Задать число нод, имя, CPU, RAM и количество Ethernet-портов.
4. Нода появится с красным индикатором и останется выключенной.
5. Нажать значок соединения на ноде либо `Соединить узлы` в меню.
6. Выбрать вторую ноду, затем конкретные свободные интерфейсы с обеих сторон.
7. Запустить ноды кнопкой `▶` или через контекстное меню `Start`.
8. Кликнуть по запущенной ноде для открытия встроенной HTML-консоли.
9. Настроить свою лабораторную и проверить связность.
10. Сохранить конфигурацию командой `commit`/`write memory` и действием
    `Export CFG`.

В отличие от исходной методички, установочное меню vESR не показывается. Оно
нужно один раз при создании vendor qcow2; здесь эквивалентный базовый ARM64-образ
уже собирает Docker Compose.

## Интерфейсы

Маршрутизатор получает логические порты `gi1/0/1`, `gi1/0/2` и далее. VPC
получает `eth0`, `eth1` и далее. Диалог соединения показывает только свободные
порты. Метка рядом с концом кабеля — имя, которое надо использовать в задании.

Внутри Docker каждому подключённому порту соответствует технический Linux
интерфейс. Стенд автоматически сопоставляет `gigabitethernet 1/0/N` с ним. Это
сопоставление видно в верхней строке консоли и в `show interfaces status`.

Каждый кабель создаёт отдельный L2 bridge. Адреса `169.254.x.x`, выдаваемые
Docker, служебные и не заменяют адреса из лабораторной. Учебные IP добавляются
самостоятельно.

## Router CLI

Router CLI работает поверх FRRouting. Доступны реальные static routes, RIP,
OSPF, BGP, IPv4 и IPv6. Консоль хранит текущий режим, поэтому команды можно
вводить по одной, как в Telnet:

```text
configure
interface gigabitethernet 1/0/1
ip address 192.0.2.1/24
exit
end
commit
```

Поддержаны совместимые команды `configure`, `commit`, `confirm`,
`reload system`, `show interfaces status` и имена `gi1/0/N`. Для полной
настройки протоколов используется синтаксис FRR/vtysh. Это функциональный
эквивалент, а не поддельная оболочка всего Eltex CLI.

## VPC CLI

Основные команды:

```text
ip 192.0.2.2/24 192.0.2.1
show ip
ping 192.0.2.1
trace 192.0.2.1
arp
save
clear
```

`save` сохраняет текущие команды в Startup Config. Для диагностики можно
переключить Console в режим `Linux shell`, где доступны `ip`, `ping`,
`traceroute`, `tcpdump`, `dig`, `curl` и другие утилиты.

## Wipe и Startup Configs

- `Export CFG` извлекает текущую конфигурацию запущенной ноды.
- `Startup Configs` показывает сохранённый текст, позволяет его редактировать,
  скачивать и включать/отключать применение после wipe.
- `Wipe` пересоздаёт контейнер из чистого образа, сохраняет ноду и кабели и
  оставляет устройство выключенным.
- При следующем `Start` включённый startup-config будет загружен автоматически.

## Остальные действия

- `Edit` — имя, описание, CPU, RAM и число портов. Нельзя убрать занятый порт.
- `Reload` — остановка и повторный запуск той же ноды.
- `Capture` — текстовый `tcpdump` выбранного порта: до 20 пакетов или 8 секунд.
- Двойной клик по кабелю — удалить соединение после подтверждения.
- Правый клик по ноде — полное меню действий.

## Проверка

```bash
./lab doctor
./lab test
./lab status
```

`./lab test` на пустом поле временно создаёт маршрутизатор и VPC, выбирает
порты, настраивает тестовые IP, проверяет ping и цикл
`Export CFG → Wipe → Start`, после чего полностью удаляет тестовую топологию.
